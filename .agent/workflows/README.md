# 📚 Workflow Documentation

This directory contains reusable workflows for improving the Sleep Pact application.

## 🎯 Which Workflow Should I Use?

### For Complete Improvement Cycles
**Use**: [`full_development_lifecycle.md`](./full_development_lifecycle.md)

This is the **comprehensive, full lifecycle workflow** that covers:
- Discovery & Planning
- Development & Implementation
- Quality Assurance
- Integration & Deployment
- Retrospective & Documentation

**Best for**: Major features, bug fixes, significant improvements

**Quick Start**: Use the prompt template in [`QUICK_START_PROMPT.md`](./QUICK_START_PROMPT.md)

### For Quick Iterations
**Use**: [`continuous_improvement.md`](./continuous_improvement.md)

This is a **simplified sprint cycle** workflow for:
- Quick fixes
- Small improvements
- Rapid iterations

**Best for**: Minor changes, quick wins, small refactors

---

## 🚀 Getting Started

### Option 1: Quick Start (Recommended)
1. Open [`QUICK_START_PROMPT.md`](./QUICK_START_PROMPT.md)
2. Copy the prompt template
3. Fill in your improvement goals
4. Paste into Cursor chat

### Option 2: Manual Workflow
1. Open [`full_development_lifecycle.md`](./full_development_lifecycle.md)
2. Copy the entire document
3. Add your improvement goals at the top
4. Send to Cursor agent

## 🔄 Workflow Features

Both workflows include:
- ✅ **Exit Criteria**: Clear checkpoints to ensure quality
- ✅ **Git Integration**: Branch management and commit guidelines
- ✅ **Firebase Support**: Database operations and configuration
- ✅ **GitHub Integration**: PR creation and deployment
- ✅ **Quality Checks**: Linting, building, testing
- ✅ **Documentation**: Issue tracking and knowledge capture

---

## 📝 Notes

- All workflows are **repeatable** - use them for each improvement cycle
- **Exit criteria are mandatory** - don't skip verification steps
- **Documentation is critical** - always update `ISSUES.md` and `.agent/rules.md`
- Workflows follow the project's coding standards in `.agent/rules.md`
